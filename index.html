FastAPI Concepts

Learn how FastAPI handles requests, validation, parameters, and responses.

Path Parameters

Path parameters are values embedded directly in the URL and used to identify a specific resource. For example, /students/S001 uses S001 as a path parameter.

@app.get("/students/{student_id}")
def get_student(student_id: str): ...
Query Parameters

Query parameters appear after ? in the URL and are used for filtering or searching. For example, /customers?city=Chicago&risk_level=high.

@app.get("/customers")
def get_customers(city: str, risk_level: str): ...
Request Validation with Pydantic

FastAPI uses Python type hints and Pydantic models to automatically validate incoming JSON bodies. If a required field is missing or has the wrong type, FastAPI returns a clear error response.

class LoanApplication(BaseModel):
  name: str
  age: int
  income: float
HTTP Status Codes

FastAPI returns standard HTTP status codes to communicate the result of every request.

200 OK 400 Bad Request 404 Not Found 500 Server Error

You can trigger these in the Students page — try submitting marks > 100, or looking up a non-existent student ID.

Automatic API Documentation

FastAPI automatically generates interactive Swagger UI documentation from your code — no extra configuration needed. Every endpoint, parameter, and response schema is visible and testable at /docs.
